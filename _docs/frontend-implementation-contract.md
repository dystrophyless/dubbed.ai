## Runtime and adapter selection

The current frontend uses Node 22.23.1 with React 19.3.1, Vite 8.3.5, Vitest 5.0.5, and Playwright 1.64.1 as resolved in the implementation environment. These are observed local versions, not a production support policy. Runtime configuration and startup smoke coverage belong to issue [#67](https://github.com/dystrophyless/dubbed.ai/issues/67).

The pre-existing scaffold and package presence were not approved at task intake and are not the source of this selection. React, Zustand, and the small shadcn-oriented runtime were selected for the user-authorized backend-free frontend implementation; the bounded choice was frozen after Root's technical review and isolated local command checks. The observed versions above do not establish a production support matrix.

`VITE_SERVICE_ADAPTER` is the single adapter selector. An unset value selects the backend-free mock. An explicitly present empty or unknown value is a configuration error; explicit `real` fails with the typed adapter-unavailable error until the separately gated real adapter exists. Invalid selections must not silently fall back to mock. The selector is owned by [`bootstrap.ts`](../frontend/src/services/bootstrap.ts) and `#67`; service construction remains [`createServices`](../frontend/src/services/index.ts), owned by `#68`.

The frontend test harness uses Vitest and a deterministic service clock. Browser-only behavior is exercised with Playwright. Test success proves only the exercised local/mock behavior; it does not prove external auth, email delivery, payment, AI processing, media conversion, rendering, or deployment behavior.

## Service boundary, identity, and operation semantics

All UI service requests go through the typed `Services` facade. Feature code must not import storage/adapter modules directly or create a parallel request path. The architecture test includes representative forbidden UI requests and direct-adapter imports as negative fixtures. The interchangeable contract and mock implementation are owned by [#68](https://github.com/dystrophyless/dubbed.ai/issues/68); UI owners consume the facade.

Domain identifiers are branded types. Mutations carry a stable `operationId`; a retry reuses that identity and must reconcile an uncertain outcome before starting a distinct operation. Read-only observations are not user activity and do not advance non-due progress. A project-list read may reconcile a persisted due job, recording its single authoritative terminal event under a deduplicated event ID. `ServiceResult` carries typed success, validation/conflict/failure, and unknown-outcome facts; callers use authoritative revisions and operation snapshots, not local completion assumptions.

Revisions are domain-specific. Project revision, source revision, selection/timing revision, preparation revision, recording candidate revision, accepted-take revision, result generation, and operation revision are not interchangeable. A stale revision cannot authorize paid processing, recording acceptance, or result publication. `PreparationSnapshot.projectRevision` is the current owning `OwnedProject.revision`; `PreparationSnapshot.operation.revision` remains the job revision. Cancellation addresses its target job separately from the cancellation command's own idempotency identity.

Before processing authorization, the service binds one millisecond interval to the selected source, quote, and authorization. Quote duration is the whole selected interval rounded up to an integer second. A stale source/selection/project revision cannot authorize. Upload replacement is eligible only before the first AI launch and must preserve the occupied project slot; filename-derived title provenance is durable and distinct from a manually saved title even when their visible text matches.

Recording draft persistence is not take acceptance. Acceptance requires the exact compatible candidate, current processing/timing revisions, and confirmed usable audio frames; byte count or an audio track alone is insufficient. Unknown writes reconcile by operation identity. The first accepted take permanently locks reprocessing. An explicit final missing take may be accepted at any turn, but its durable receipt must freeze exactly one initial assembly authorization before navigation, grant release, or sign-out. A completed-project revision starts only through explicit **To result**, not a completed **Next** render.

Result assembly and download are identity-bound. The initial authorization and retries preserve one retry lineage; a retry uses the same identity until an authoritative result is known. Download pins the generation displayed when the download action is activated. Ready background completion does not steal navigation or autoplay a newly available result.

The selected source interval is one canonical 0.001-second range across the fields, saved project, quote, and authorization. The end boundary cannot exceed the source end floored to milliseconds; the whole selected duration is rounded up once for billing, with neither boundary billed separately. Dialogue capture runs to its fixed turn window without a manual Stop. Zero-turn reprocessing preserves the prior usable preparation and draft. When the final missing take is accepted through Back, Save and go, Save and leave, sign-out, or another explicit navigation guard, the service records initial assembly durably but the requested destination wins; ordinary final **Next** opens Result. An assembly authorization or running operation is not itself a displayed generation: Result displays the authoritative activated generation, and download remains pinned to the generation displayed at activation time.

Credit settlement is bounded by the service-authorized reservation/quote; a UI-supplied charge is never authority. Purchase fulfillment requires a service-authoritative verification proof, not a redirect or UI shortcut. Pack amounts, prices, provider, tax/refund/reversal policy, and processing-stage allocation remain synthetic or open as listed below.

## Persistence and deterministic mock conventions

The default mock persists accounts, sessions, projects, source/candidate blobs, preparations, operations, ledger entries, purchase attempts, and media descriptors in IndexedDB. Workspace/project/ledger records are account-owned within the selected namespace and are not hidden from a second same-account client merely because its client ID differs. Sessions and mutation journals are client-bound; all records are still account-checked on access. A new browser context is not evidence of cross-device or production storage and recovery.

Mutation journals bind operation identity to account/client, request fingerprint, state, and authoritative result. Anonymous reconciliation is narrowly bound to the originating client and opaque operation/reference; it reveals no other account's facts. File and Blob request fingerprints include content bytes (hashed before the IndexedDB transaction), not only MIME type and byte length. Same-operation reuse with different bytes conflicts. Account deletion and session expiry are not inferred from a stale client-side session alone.

The injected service clock drives deterministic expiry, cooldown, retry, and due-time behavior. Background preparation records its due time durably; project-list reconciliation may apply due terminal work once, while observation/list refresh does not manufacture non-due progress or duplicate a terminal activity event. A monotonic workspace activity sequence plus a stable-ID tie-break is the selected mock ordering mechanism; deduplicated event IDs prevent duplicate terminal observations from reordering a project.

All fixed media and checkout outcomes are labeled synthetic. Compatible-preview scenarios are limited to the exact permitted known fixture and preserve the same source video identity, bytes, duration, geometry, and timeline; they do not claim arbitrary transcoding. Generated Result fixture videos are not actual renders from user-uploaded audio. Mock OAuth, OTP, email, checkout, prices, balance grants, processing stages, and deterministic failures are scenarios only, not production security or financial policy.

The persistent workspace, credit ledger and scenario behavior are owned by [#73](https://github.com/dystrophyless/dubbed.ai/issues/73) and [#70](https://github.com/dystrophyless/dubbed.ai/issues/70), with fixture data owned by [#72](https://github.com/dystrophyless/dubbed.ai/issues/72). Media inspection, microphone capture, and rendering remain bounded by their respective flow and evidence issues.

# Dubbed design system

Dubbed lets people dub short video scenes with their own voice (`PRODUCT_BRIEF.md`). Its UI follows **affect-ui Clean /
Light**: a light grey canvas, white cards with a 10px radius and a hairline shadow, compact 13px Inter, alpha-black greys,
a dark-chip primary button, one blue accent for state, **red for recording and destructive actions**. Light theme only.
UI in **English and Russian**. This folder is the single source of truth for designing and building UI.

## Golden rules

1. **Every page is an archetype.** Start from its reference template; never invent a page layout. No fit → NEW-ARCHETYPE.
2. **Compose, don't create.** Kit + layout + media components. A new component needs a ui-spec entry and a styleguide section.
3. **Tokens only.** No raw colours, radii, shadows, font sizes or weights; spacing via `gap` props or `--space-*`.
4. **affect-ui ports are untouchable** (`src/components/ui/affect/*`, generated by `scripts/port-affect.py`). A deviation is
   a documented, owner-approved DUBBED PATCH (`components.md`).
5. **The card is the one surface.** White, 10px, `--shadow-card`. No card-in-card: inner groups use a divider or a wash.
6. **Primary = the dark chip; red = recording and destruction; blue = state** (checked, progress, focus, saved take).
7. **Every state is designed:** loading (skeleton in content shape), empty, error (with retry), success.
8. **Desktop 1440 × 900 and phone 390 × 844** for every screen; layouts switch at 1024.
9. **Copy is design:** EN + RU for every string through i18n keys, sentence case, verbs on buttons, glossary terms.
10. **E2E-ready:** semantic roles and labels first, `data-testid` per `quality.md`, states driven by data.
11. **Every control works.** If the feature can't do it yet, don't show the control.
12. **No browser-native pickers** (own `Select`, `Menu`; the OS file dialog is the only exception).
13. **No speaker identity anywhere** — no names, no "Speaker 1".
14. **Fidelity over contrast fixes:** affect's low-contrast greys stay; axe `color-contrast` is a documented exception.

## Page-quality rules (from review rounds — apply always)

- **One primary action per view**, unmistakable; the most frequent action (Record) is never pale or tiny.
- **No duplicated information** on one screen (the same counter, status or hint twice).
- **Key actions are visible without scrolling** at 1440 × 900 and 390 × 844.
- **Buttons in one row have the same size; controls in one toolbar have the same height.**
- **Navigation actions** (Previous / Next) look like actions, not like disabled text.
- **Neighbouring sections share their header shape** (all with a description, or none).
- **Media at its own aspect ratio** — no heavy letterbox frames, nothing printed over the picture.
- **Phone:** no horizontal scroll; Clean touch sizes (36px buttons, 44px rows); text readable without zoom; inputs 16px.

## Matched recovery drills after baseline

1. Return and record a replacement for line2. Fail next save in Prototype controls,then Previous→Save and go. Observe whether the person understands the exact retained replacement,prior saved take and retry destination. Let the8-second popup expire;durable guidance/action must remain. Reload,then Retry;it saves that same candidate and returns to line1.
2. Block next capture,then Record. No recording should start or take disappear. Observe Settings recovery;there is no microphone check/setup on Record. With an unaccepted candidate,Settings is guarded. The once-only onboarding check is outside this slice.
3. Fail next assembly,then To result. All saved takes remain;Retry assembly is an ordinary footer action outside the message. Reload retains the failed state without automatic retry. Retry or Return must preserve accepted takes.
4. On a fresh run,complete the final take through an explicit leave-to-projects guard. Save failure/retry must keep that destination rather than replace it with Result. A uses global My projects;B uses Exit. Neither route is a full Projects implementation.
